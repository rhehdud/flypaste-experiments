# 초파리 커넥톰으로 포켓몬 페이스트 복원 — 실험 코드

[![License](https://img.shields.io/badge/License-Apache--2.0-929292)](LICENSE)
[![Project Page](https://img.shields.io/badge/Project%20Page-flypaste-929292)](https://eunhavgc.github.io/flypaste)

MaleCNS 수컷 초파리 커넥톰에서 버섯체(mushroom body)를 떼어내 실제 배선 그대로 시뮬레이션하고,
초파리가 냄새를 배울 때 쓰는 도파민 규칙으로 **오픈 팀 시트(OTS)에 가려진 노력치 배분과 성격을 맞히게** 학습시킨다.

이 저장소는 그 **학습·평가 실험 코드**다. 목표는 정확도 자체가 아니라
초파리 버섯체가 이 과제를 잘하게 만드는 방법을 찾는 것이었다.

---

## 이 저장소에 있는 것과 없는 것

| 있는 것 | 없는 것 |
|---|---|
| 커넥톰 → 버섯체 부분망 추출, LIF 시뮬레이션, 도파민 학습, 교차검증, 환경 변화 실험, 시험 평가, 기준선 — 실험 코드 전부 | 학습 데이터, 학습된 가중치, 커넥톰 원본, 추론 도구 |

**클론해서 바로 돌아가는 저장소가 아니다.** 커넥톰은 공개처에서 받고(아래), 데이터는 각자 준비해야 한다.
여기서 하려는 것은 **"이 방법으로 학습이 된다"를 돌려 볼 수 있는 형태로 남기는 것**이다.

## 무엇을 맞히는가

Pokémon Champions의 페이스트에서 OTS에 공개되는 것은 종족·아이템·특성·기술 4개다.
가려진 것은 **노력치 배분**(6스탯 합 66, 스탯당 32 이하)과 **성격**(21종) 두 가지다.

한 마리씩 예측하되 **같은 팀 나머지 5마리도 입력으로 쓴다.** 팀 구성이 그 마리의 역할을 알려주기 때문이다.
노력치는 미리 정한 배분 목록에서 고르지 않는다. 규칙(합 66, 스탯당 32 이하)에 맞는 모든 배분을 낼 수 있다.

두 갈래로 나눠 본다. **성격을 알 때**(OTS에 성격이 적혀 있고 노력치만 맞힘)와 **성격을 모를 때**(둘 다 맞힘).
성격이 스탯 하나를 올리고 하나를 내리므로, 성격만 알아도 어느 스탯에 투자했는지가 상당히 좁혀진다.

## 초파리가 이걸 어떻게 하는가

1. **입력 매핑** — OTS의 이름(`sp:Sneasler`, `mv:Close Combat` …) 하나마다 투사뉴런 5개를 시드 고정으로 배정한다.
   후보는 Kenyon cell에 실제로 시냅스를 50개 이상 보내는 ALPN 241개뿐이다.
2. **시뮬레이션** — 배정된 투사뉴런을 150Hz Poisson으로 1초 자극하고, 버섯체 부분망 5,191뉴런을
   Shiu et al. 2024 방식 LIF로 돌린다. 나온 **Kenyon cell 4,064개의 발화율이 그 마리의 코드**다.
   팀 6마리의 특징 합집합도 61Hz로 따로 자극해 옆에 붙인다.
3. **학습** — Kenyon cell → 출력 시냅스만 도파민 규칙으로 바꾼다. 배선은 건드리지 않는다.
   `W += eta x 발화율 x 도파민`, 가중치는 0 이상, 한 마리씩.
4. **답 고르기** — 출력은 스탯마다 0~32 값의 확률이다. 합 66·스탯당 32 이하를 만족하는 조합 중
   가장 좋은 것을 동적 계획법으로 찾는다.

성격 출력층은 성격 21개를 각각 배우지 않고 **"올리는 스탯 6 + 내리는 스탯 6" 12구획**으로 배운다.
"특공을 내린다"는 구획을 Adamant·Jolly·Impish·Careful이 함께 배우므로 드문 성격도 신호를 나눠 받는다.

## 커넥톰 받기

저장소에 커넥톰은 없다(약 1.1GB). [Janelia FlyEM MaleCNS v1.0](https://www.janelia.org/project-team/flyem/male-cns-connectome)의
[다운로드 페이지](https://male-cns.janelia.org/download/)에서 셋을 받아 **아래 이름으로** 둔다. 코드가 이 이름으로 연다.

```bash
mkdir -p connectome_data/malecns_v1 && cd connectome_data/malecns_v1
B=https://storage.googleapis.com/flyem-male-cns/v1.0/connectome-data/flat-connectome
curl -L -o annotations.feather       "$B/body-annotations-male-cns-v1.0-minconf-0.5.feather"
curl -L -o neurotransmitters.feather "$B/body-neurotransmitters-male-cns-v1.0.feather"
curl -L -o edges.feather             "$B/connectome-weights-male-cns-v1.0-minconf-0.5.feather"
```

`minconf-0.5`는 시냅스 신뢰도 0.5 이상만 남긴 판이다. 다른 판을 받으면 노드·엣지 수부터 달라진다.

```bash
python src/connectome.py     # 노드 166,700 / 엣지 25,582,938 이면 제대로 받았다
```

버섯체 부분망(5,191뉴런)은 `mb.py`가 여기서 뽑아내 `out/mb_graph.npz`에 캐시한다.

```bash
python src/mb.py             # 부분망 크기와 Kenyon cell 희소도 확인
```

## 데이터 준비

데이터는 공개하지 않는다. 자기 데이터를 넣으려면 **두 열 `OTS`, `paste`를 가진 xlsx**를 만들고
`pipeline.py`에 `경로:이름` 꼴로 넘긴다. 이름은 `source` 열에 그대로 들어간다.

| 열 | 내용 |
|---|---|
| `OTS` | 공개된 부분만 담은 Showdown 페이스트 (종족·아이템·특성·기술) |
| `paste` | 노력치·성격까지 있는 원본 페이스트 (정답) |

```bash
python src/pipeline.py data/old.xlsx:OLD data/new.xlsx:NEW --out-dir out   # 학습·검증용
python src/pipeline.py data/heldout.xlsx:TEST --out-dir out/test           # 시험용 (따로 둔다)
```

이름 세 개는 코드가 알아본다. `OLD`는 먼저 모인 데이터, `NEW`는 나중에 모인 데이터,
`TEST`는 시험용이다. [4. 환경이 바뀔 때](#4-환경이-바뀔-때)와
[7. 새 데이터가 얼마나 필요한가](#7-새-데이터가-얼마나-필요한가)가 `OLD`/`NEW` 구분을 쓴다.
다른 이름을 쓰려면 환경변수 `FLY_OLD_SOURCE`·`FLY_NEW_SOURCE`·`FLY_TEST_SOURCE`로 바꾼다.

파싱·정규화 후 `out/mons_clean.parquet`(마리별)과 `out/teams_clean.parquet`(팀별)이 나오고,
이후 모든 실험이 이 두 파일을 읽는다. 종족의 메가 폼 이름은 기본 이름으로 합친다.
**형식이 맞지 않는 페이스트는 불량으로 표시해 학습·평가에서 뺀다**(`valid` 열).

```bash
python src/mb_task.py        # 데이터 요약, 기준선, 입력이 같은 개체의 정답 일치율(어떤 모델도 넘을 수 없는 선)
```

학습 데이터와 시험 데이터는 **서로 다른 시기**에서 가져오는 것이 좋다. 쓸 수 있는 포켓몬이 바뀌면
시험 데이터에 학습에 없던 종족이 섞이는데, 그게 실제로 마주치는 상황이다.
"처음 보는 종족" 약점은 이 경우를 말한다.

## 실험

전부 프로젝트 루트에서 실행한다. Kenyon cell 코드는 `out/kc_codes_*.npz`에 캐시되고,
가공이 바뀌면 입력 해시로 알아서 다시 계산한다.

### 1. 기준선 — 암기표가 어디까지 가는가

넘어야 할 기준선은 **포켓몬 이름만 보고 아는 최빈 노력치·최빈 성격**이다.
학습 데이터에서 그 종족(+성격)이 가장 많이 쓴 배분을 그대로 답으로 내는 암기표다.

```bash
python src/baseline.py
```

### 2. 초파리 없이 — 고르는 순서

같은 입력을 로지스틱 회귀가 읽을 때, 노력치와 성격을 어느 순서로 고르는 것이 나은지 비교한다.
스탯별 노력치 + 성격 따로 / 성격 먼저 → 노력치 / 노력치 먼저 → 성격 / 완전히 함께.
초파리도 여기서 정한 순서(성격 먼저 → 노력치)를 쓴다.

```bash
python src/spread.py
```

시험 데이터에서의 비교는 [6. 시험 평가](#6-시험-평가)가 한다.

### 3. 버섯체 학습

실험의 중심이다. 도파민 학습 + 교차검증.

```bash
python src/mb_learn.py
```

시험 fold는 **같은 잡음**과 **개체마다 새 반응** 두 가지로 채점한다(후자가 기본 지표).

| 옵션 | 무엇을 보는가 |
|---|---|
| `--compare` | 비교 기준(최빈값·로지스틱 회귀)을 같은 fold에서 함께 채점 |
| `--shuffle` | 투사뉴런→Kenyon cell 연결만 섞은 배선. 출력 수·가중치는 그대로 |
| `--nature both --nature-only` | 성격 출력층 비교: 성격마다 한 구획(21) vs 올림·내림 12구획(기본) |
| `--code perfeature` / `--code sequence --seq-ms 200` | 특징마다 따로 자극한 코드의 합 / 한 시뮬레이션 안에서 차례로 |
| `--etas 3e-5,1e-5,3e-6` | 학습률 후보 지정 |
| `--select`, `--select-ev` | 성격·노력치를 고르는 손실 (기본 로그 손실) |
| `--test-draws 2`, `--train-draws 2` | 새 반응 여러 번 평균 / 학습 반응 섞기 |
| `--ctx-temps` | 노력치 맥락으로 쓰는 성격 확률의 온도별 채점 |
| `--save-lp` | 시험 개체의 성격·노력치 확률을 저장 (고르는 규칙을 따로 비교할 때) |

### 4. 환경이 바뀔 때

쓸 수 있는 포켓몬이 바뀌면 새 종족·새 기술이 들어온다. 그때 어떻게 따라가는지 보는 실험이다.

```bash
python src/mb_shift.py       # 앞 시기로 학습 -> 다음 시기로 시험
python src/mb_stream.py      # 새 데이터를 한 마리씩 먼저 예측한 뒤 배우기
python src/mb_stream.py --confirm   # 튜닝 절반으로 고르고 확인 절반으로 한 번 확인
python src/mb_stream_cv.py   # 위 예측을 종족 5겹으로 교차 평가
```

`mb_shift.py`는 처음 보는 이름을 그대로 둔 경우와 뺀 경우, 새 종족·새 기술 개체를 따로 채점한다.
`--decay`는 개체 하나를 배울 때마다 Kenyon cell→출력 가중치를 (1-decay)배로 줄인다.
`--decay-rare`는 그 감쇠를 드물게 쓰이는 Kenyon cell에만 건다.

### 5. 최종 모델

기본 설정으로 전체 학습 데이터를 학습하고 저장만 한다. **시험 데이터는 보지 않는다.**

```bash
python src/mb_final.py
```

기본값은 12구획 성격 출력층, 팀 자극 61Hz, 성격·노력치 모두 로그 손실이다.
`--no-team`, `--select`, `--select-ev`, `--nature`, `--etas`로 바꾸면 **저장 파일 이름도 달라져** 덮어쓰지 않는다.

### 6. 시험 평가

`mb_test_stream.py`와 `mb_test_metrics.py`는 [5. 최종 모델](#5-최종-모델)이 저장한 모델을 읽으므로
`mb_final.py`를 먼저 돌려야 한다. `mb_test.py`는 스스로 학습한다.

```bash
python src/mb_test.py           # 학습 -> 시험 데이터를 고정 모델로 예측
python src/mb_test_stream.py    # 저장된 모델의 버리는 사본으로 팀 단위 2겹 평가
python src/mb_test_metrics.py   # 모델 고정, 예측만 -> out/test/metrics_{TAG}.json
```

`mb_test_stream.py`는 A팀들로 배우고 B팀들을 채점하고 반대로도 한다.
**모델 파일은 바뀌지 않고, 배운 가중치는 저장하지 않는다.**

`mb_test_metrics.py`는 학습도 가중치 갱신도 하지 않고 지표 JSON만 쓴다.
같은 입력을 로지스틱 회귀가 읽는 비교 줄 두 개(OTS 특징 / 버섯체 코드)를 함께 내므로
[결과](#결과)의 표가 그대로 나온다. 로지스틱이 필요 없으면 `--no-compare`로 뺀다.
초파리 쪽 숫자는 자극 잡음에 따라 흔들리므로 `--seed-offset 1,2,3`으로 뽑기를 늘려 평균한다.

### 7. 새 데이터가 얼마나 필요한가

새 환경 데이터가 얼마나 모였을 때 어떻게 배우는 것이 나은지 비교한다.
계속 배우기 vs 모아서 한꺼번에 다시 학습.

```bash
python src/mb_update.py                   # 학습 몫 0.1~1.0
python src/mb_update.py --teams 5,10,20,30   # 비율 대신 새로 모인 팀 수 (희소한 새 환경)
python src/mb_update.py --report           # 저장된 예측으로 표만 (실행 중이면 부분 표)
```

작업마다 바로 저장하므로, 다시 실행하면 끝난 작업은 건너뛴다.

**환경이 바뀔 때 어떻게 따라가야 하는가**([7. 새 데이터가 얼마나 필요한가](#7-새-데이터가-얼마나-필요한가))다.

### 시험 데이터에서

시험 데이터에서 **입력도 답도 학습 데이터와 똑같은 개체를 뺀 뒤** 채점한다 (외울 수 있는 중복).
설정·규칙은 전부 다른 데이터에서 고른 뒤 여기서 확인만 했다.

비교는 `입력 x 학습 규칙`으로 놓는다. **세 줄 모두 같은 정보를 받는다** — 그 마리와 같은 팀 5마리.

| 입력 | 학습 규칙 | 초파리가 하는 일 |
|---|---|---|
| OTS 특징 (이름 그대로) | 로지스틱 회귀 | 없음 |
| 버섯체 Kenyon cell 코드 | 로지스틱 회귀 | 배선으로 코드만 만든다 |
| 버섯체 Kenyon cell 코드 | 도파민 학습 | 코드 + 학습 |

#### 성격을 알 때 — 노력치만 맞힌다

| | EV(노력치) 오차 ↓ | 완전일치 ↑ | 어디에 줄지 ↑ | 어색한 조합 ↓ |
|---|---|---|---|---|
| 버섯체 코드 + 도파민 학습 | **12.54** | **24.8%** | **48.6%** | **0.0%** |
| OTS 특징 + 로지스틱 회귀 | 13.39 | 16.4% | 35.6% | 0.7% |
| 버섯체 코드 + 로지스틱 회귀 | 13.57 | 21.2% | 37.0% | 5.3% |

#### 성격을 모를 때 — 성격과 노력치를 다 맞힌다

| | EV(노력치) 오차 ↓ | 완전일치 ↑ | 어디에 줄지 ↑ | 성격 ↑ | 어색한 조합 ↓ |
|---|---|---|---|---|---|
| 버섯체 코드 + 도파민 학습 | **15.90** | **18.2%** | **33.9%** | **55.0%** | 10.6% |
| OTS 특징 + 로지스틱 회귀 | 16.73 | 13.0% | 26.7% | 45.9% | **2.1%** |
| 버섯체 코드 + 로지스틱 회귀 | 19.24 | 14.7% | 26.7% | 51.2% | 5.1% |
| 종족 최빈 배분 (암기표) | 23.29 | 13.7% | 26.7% | 53.4% | 2.7% |

- **EV(노력치) 오차** = \|예측 − 정답\| 합 ÷ 2 (66점 만점 기준의 총 어긋남). 프로그램 출력에는 `EV 오차`로 찍힌다
- **완전일치** = 6스탯이 모두 정확히 일치
- **어디에 줄지** = 노력치를 준 칸과 안 준 칸이 6스탯 모두 정답과 같은 비율
- **어색한 조합** = 자기가 낸 성격이 올리는 스탯에 노력치를 거의 안 준 배분

초파리 쪽과 `버섯체 코드 + 로지스틱`은 자극 잡음에 따라 흔들리므로 **잡음을 달리한 네 번 실행의 평균**이다
(도파민 노력치 오차 12.32~12.95 / 15.44~16.23). OTS 특징 줄과 암기표는 잡음이 없어 실행마다 같다.
표는 `mb_test_metrics.py`가 저장한 `out/test/metrics_*.json`에서 나온다.

#### 무엇이 기여했는가

**도파민 학습 규칙이다.** 같은 Kenyon cell 코드를 로지스틱 회귀로 읽으면 13.57 / 19.24인데,
도파민 규칙으로 읽으면 12.54 / 15.90이 된다.

**희소 코드 자체는 이득이 아니다.** 원래 이름 특징을 로지스틱 회귀로 읽은 13.39 / 16.73과 비교하면,
코드를 거친 쪽이 성격을 모를 때 오히려 나쁘다(19.24). 4,064개로 무작위 투영하면서 정보가 깎인다.
도파민 규칙은 그 손실을 메우고 넘어선다.

**초파리가 확실히 앞서는 축은 "어디에 줄지"다.** 48.6% / 33.9%로 로지스틱 두 줄(26.7~37.0%)보다 높다.
어느 스탯에 투자했는지의 패턴을 가장 잘 읽는다.

**처음 보는 종족에서도 가장 낫다.** 노력치 오차가 14.62 / 20.67로, 로지스틱(17.15 / 23.62)과 암기표(34.34)보다 낮다.
그래도 아는 종족(11.27 / 13.45)과는 차이가 크다 — [알려진 약점](#알려진-약점) 참고.

**관습을 벗어난 개체에서 벌어진다.** 정답이 그 종족의 최빈 배분과 다른 개체만 모으면 13.88 / 17.82인데,
암기표는 정의상 여기서 26.98이다. 반대로 정답이 관습 그대로인 개체는 암기표가 만점이라 진다.

#### 초파리가 지는 칸

- **성격을 스스로 맞힐 때 앞뒤가 안 맞는 배분을 가장 많이 낸다** (어색한 조합 10.6%).
  성격을 알려 주면 0.0%이므로, 성격 예측이 흔들릴 때 노력치가 함께 끌려가는 것이다.

### 계속 배울까, 다시 학습할까

새 환경 데이터가 쌓일 때 **계속 배우는 것**과 **모아서 처음부터 다시 학습하는 것**을 같은 평가 몫으로 비교했다.
새 환경 데이터를 종족 5겹으로 나눠, 4겹을 "새로 모인 데이터"로 쓰고 1겹으로 채점한다.
표의 칸은 `성격 정확도 / EV(노력치) 오차`이고, 행은 새로 모인 데이터 중 실제로 쓴 비율이다.

#### 처음 보는 종족 — 효과가 가장 큰 곳

| 쓴 비율 | 계속: 두 구획 | 계속: 한 번씩 | 모아서 다시 (옛 환경 포함) | 모아서 다시 (새 환경만) |
|---|---|---|---|---|
| 0 (안 배움) | 27.2% / 20.29 | 27.2% / 20.29 | 27.2% / 20.29 | 27.2% / 20.29 |
| 10% | 47.6% / 16.64 | 39.7% / 17.99 | 56.7% / 14.76 | **60.0% / 14.86** |
| 100% | 60.0% / 12.97 | 56.7% / 14.06 | **65.7% / 11.29** | 66.1% / 11.22 |

#### 새 환경 전체

| 쓴 비율 | 계속: 두 구획 | 계속: 한 번씩 | 모아서 다시 (옛 환경 포함) | 모아서 다시 (새 환경만) |
|---|---|---|---|---|
| 0 (안 배움) | 56.9% / 14.02 | 56.9% / 14.02 | 56.9% / 14.02 | 56.9% / 14.02 |
| 10% | 62.2% / 12.79 | 61.0% / 12.96 | **65.3% / 12.13** | 61.9% / 15.16 |
| 100% | 66.7% / 11.53 | 66.0% / 11.75 | **69.6% / 10.53** | 68.1% / 11.25 |

**모아서 다시 학습하는 쪽이 계속 배우기보다 항상 낫다.** 전체에서 10.53 대 11.53, 성격 69.6% 대 66.7%다.
한 마리씩 배우는 방식은 편하지만 같은 데이터로 얻을 수 있는 것을 다 못 가져간다.

**계속 배워야 한다면 두 구획이 한 번씩보다 낫다.** 처음 보는 종족에서 12.97 대 14.06으로 차이가 가장 크다.
낯선 입력에서만 열리는 빠른 구획이 새 종족을 따라잡는 데 쓸모가 있다.

**데이터가 조금만 모여도 새 종족이 크게 개선된다.** 10%만 써도 성격이 27.2% → 56.7%, 노력치 오차가 20.29 → 14.76이다.
반대로 **옛 환경 데이터를 버리면 초반에 손해다** — 10%에서 전체 노력치 오차가 15.16으로, 아예 안 배운 14.02보다도 나쁘다.
새 환경만으로 처음부터 배우기에는 표본이 너무 적다. 데이터가 쌓이면(100%) 그 손해가 사라진다.

## 알려진 약점

**표본이 적은 기술을 너무 믿는다.**

학습 데이터에 드물게 나온 기술이 예측을 한 방향으로 끌고 가는 경우가 있다.
특히 **입력 대부분이 모델에 없는 이름인 개체**에서 심하다 — 종족·특성·기술 중 학습에 없던 것이 많으면
남은 신호가 그 드문 기술 하나뿐이 되고, 그 기술이 소수 표본에서 가진 편향이 그대로 답이 된다.
같은 기술 구성이어도 종족 이름을 아는 개체는 그 닻이 있어 끌려가지 않는다.

원인은 도파민 규칙의 성질이다. 흔한 특징의 Kenyon cell은 여러 개체를 배우면서 갱신이 서로 상쇄되는데,
드문 특징은 몇 번의 갱신이 한 방향으로만 쌓인다. **표본이 적을수록 오히려 가중치가 극단적이 된다.**

시냅스 감쇠(`mb_shift.py --decay`)로 고쳐 보려 했으나 실패했다. 처음 보는 종족은 좋아지지만
아는 이름 쪽이 유의하게 나빠져 전체로는 손해였다. 감쇠는 시간에만 반응하고 표본 수를 가리지 못한다.
**미해결이다.**

## 구조

`data/`와 `connectome_data/`는 저장소에 없다. 각자 준비해 아래 자리에 둔다.

```
.
├── src/
│   ├── pipeline.py            # 페이스트 파싱·정규화·내보내기 (모든 실험의 입구)
│   ├── connectome.py          # MaleCNS 로더
│   ├── simulate.py            # LIF 시뮬레이션
│   ├── mb.py                  # 버섯체 부분망과 Kenyon cell 코드
│   ├── mb_task.py             # 데이터·특징·분할 도구
│   ├── spread.py              # 스탯별 확률 + 성격 -> 규칙에 맞는 배분
│   ├── model_io.py            # 모델 저장·불러오기 (safetensors)
│   ├── mb_learn.py            # 도파민 학습 + 교차검증  <- 실험의 중심
│   ├── mb_shift.py            # 쓸 수 있는 포켓몬이 바뀔 때
│   ├── mb_stream.py           # 한 마리씩 예측 후 학습
│   ├── mb_stream_cv.py        # 위 예측의 종족 5겹 교차 평가
│   ├── mb_update.py           # 데이터 양별 학습 방식 비교
│   ├── mb_final.py            # 기본 설정으로 최종 학습·저장
│   ├── mb_test.py             # 시험 평가
│   ├── mb_test_stream.py      # 시험 데이터 팀 2겹 평가
│   ├── mb_test_metrics.py     # 지표 JSON 생성
│   └── baseline.py            # 최빈값 기준선
├── LICENSE
├── requirements.txt
│
├── data/                      # 각자 준비 (저장소에 없음)
│   ├── old.xlsx               #   두 열: OTS, paste — 먼저 모인 데이터
│   ├── new.xlsx               #   나중에 모인 데이터
│   └── heldout.xlsx           #   시험용
│
├── connectome_data/           # 각자 받기 (저장소에 없음, 약 1.1GB)
│   └── malecns_v1/
│       ├── annotations.feather
│       ├── edges.feather
│       └── neurotransmitters.feather
│
└── out/                       # 산출물 (pipeline.py가 만든다)
    ├── mons_clean.parquet     #   마리별
    ├── teams_clean.parquet    #   팀별
    ├── mb_graph.npz           #   버섯체 부분망 캐시
    ├── kc_codes_*.npz         #   Kenyon cell 코드 캐시
    └── test/                  #   시험 데이터는 따로 (--out-dir out/test)
```
